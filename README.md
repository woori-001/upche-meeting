# 업체회의 누적분석

협력점·판매점·제휴 업체의 월별 접수 실적, 신규·이탈, 증감, 취소율·해지율과 유통마진을 보는 웹앱입니다.

- **화면**: 이 저장소의 `index.html` (깃허브 페이지로 공개)
- **데이터**: Supabase 프로젝트 `woori-001's Project` 의 `upche_` 로 시작하는 테이블
- **로그인**: 앱 전용 계정 (Supabase 이메일 로그인과는 별개라 다른 앱에 영향 없음)

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 화면 전체 (디자인·계산·엑셀 저장). Supabase 주소와 공개용(publishable) 키가 들어 있음 |
| `supabase/upche_schema.sql` | 테이블·보안(RLS)·서버 함수. Supabase SQL Editor 에서 실행 |
| `apps-script/Code.gs` | 예전 구글시트 서버 (구글시트 → Supabase 옮길 때만 씀, 옮긴 뒤엔 안 씀) |

## 처음 설정 (한 번만)

### 1. Supabase 에 서버 함수 넣기
1. Supabase 대시보드 → `woori-001's Project` → 왼쪽 **SQL Editor** → **New query**
2. `supabase/upche_schema.sql` 내용을 전부 붙여넣기
3. 맨 아래 `'여기에_임시비밀번호'` 를 원하는 임시 비밀번호로 바꾸기
4. **Run** → `Success. No rows returned` 가 나오면 끝
   (여러 번 실행해도 안전합니다. 있는 테이블·데이터는 그대로 두고 함수만 새로 고칩니다)

### 2. 화면 올리기
`index.html` 을 이 저장소에 올리면(덮어쓰기) 1~2분 뒤 `https://woori-001.github.io/upche-meeting/` 에 반영됩니다.

### 3. 로그인 · 데이터 옮기기
1. 아이디 `admin`, 1번에서 정한 임시 비밀번호로 로그인 → 새 비밀번호로 바꾸기
2. 왼쪽 아래 사람 모양 버튼 **[계정 관리]** → 아래 **[구글시트 데이터 옮겨오기]**
3. 예전 화면에서 쓰던 아이디·비밀번호를 넣고 **옮기기 시작**
   → 접수 데이터 · 협력점정보 · 유통마진(사유·메모 포함)이 그대로 옮겨집니다
4. 같은 **[계정 관리]** 에서 팀원 계정을 만들어 주세요 (처음 로그인 때 각자 비밀번호를 정함)

## 회의 결정 기능 (통신사별 점검 · 회의 결과)
- 업체회의 화면의 **이번 회의 결정** 칸, 왼쪽 메뉴의 **통신사별 점검** · **회의 결과** 에서 씁니다.
- 결정은 `public.upche_decisions` 테이블에 업체 × 통신사별로 저장됩니다 (유지 / 등급변경 / 정책중단(휴면) / 유예).
- 이 기능을 처음 쓸 때 `supabase/upche_schema.sql` 을 SQL Editor 에서 **한 번 더 실행**해야 합니다. 있는 데이터는 그대로 둡니다.

## 유통매출 (손익매출 계산기)
- 왼쪽 위 전환 버튼의 **유통매출**을 누르면 `pnl/` 폴더의 손익매출 계산기가 화면 가득 열려요.
  - `pnl/` 은 예전 계산기 저장소(`woori-001/dist_pnl`)를 그대로 가져온 것이고, **계산 규칙(`pnl/src/rules.js`·`calc.js`·`eval.js`)은 손대지 않았어요.**
  - 바뀐 것은 로그인·저장 부분뿐이에요. 업체회의 웹 계정으로 쓰고, 저장은 `supabase/upche_pnl.sql` 의 서버 함수(`upche_pnl_*`)로 해요.
  - 저장 데이터는 예전과 같은 `dist_pnl_runs` / `dist_pnl_lines` 표를 같이 써서, 예전 계산기 주소(https://woori-001.github.io/dist_pnl/)도 그대로 동작해요.
- 「유통손익 가져오기」 즐겨찾기는 유통매출 화면 왼쪽에서 **새로 끌어다 놓아야** 새 주소로 열려요.

## 코드실적
- 전환 버튼의 **코드실적**을 누르면 `code/` 폴더의 코드실적 계산기(원본: wooriwoosin/code, 만든 분 동의 받음)가 본문에 열려요. 계산 규칙은 원본 그대로예요.
- 계산한 결과는 **월별로 저장**(`supabase/upche_code.sql` 의 `upche_code_*`)돼서 왼쪽 달력에서 다시 볼 수 있어요. 고객 이름 등 행 자료는 저장하지 않고 집계만 저장해요.

## 어드민에서 가져오기 (오른쪽 바)
- 유통마진 · 유통매출 · 코드실적 화면 오른쪽 바의 **「업체회의 가져오기」** 버튼을 즐겨찾기 막대에 끌어다 두고, 어드민(workline.kr)에서 누르면 돼요.
- 받은 엑셀은 작은 중계 창(`pnl/relay.html`)을 거쳐 **이미 열려 있는 업체회의 웹 탭**으로 바로 들어가요. 열린 탭이 없으면 그 창이 업체회의 웹으로 바뀌어요.
- 날짜 기준: 일반 = 개통일, 추가·환수 = 정산예정일 (유통마진만 고르면 일반 2개만).

## 보안 구조
- 데이터 테이블(`public.upche_*`)은 **RLS 를 켜고 정책을 두지 않아** 화면의 공개 키로는 직접 읽거나 쓸 수 없습니다.
- 계정·세션(`private.upche_*`)은 API 로 노출되지 않는 `private` 스키마에 있고, 비밀번호는 bcrypt 로 저장합니다.
- 화면은 `upche_` 로 시작하는 서버 함수만 부를 수 있고, 함수가 로그인 토큰(6시간, 쓸 때마다 연장)을 확인한 뒤 대신 읽고 씁니다.
- 로그인 실패가 10분 안에 10번 넘으면 그 접속 위치는 10분간 막힙니다.
- 계정 만들기·지우기는 관리자 계정만 할 수 있습니다.
- `고객키` 칸에는 재접수 판정용으로 연락처 앞 7자리 + 가린 이름만 저장됩니다.
